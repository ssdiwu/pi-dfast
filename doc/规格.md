# pi-dfast 现行规格

本文件是 `pi-dfast` 当前机制与边界的唯一正文。`README.md` 只面向使用者给命令、安装与验证；`AGENTS.md` 只给协作约定；两处不再重复本文的机制条款。

实现细节以代码为准：`src/fast-mode.ts`（模型资格与请求注入纯逻辑）、`src/session-state.ts`（会话状态记录与恢复）、`index.ts`（Pi 生命周期及跨扩展事件协议）。

## 会话与状态边界

- 每个新会话都默认关闭，不存在全局或项目级默认值。
- `/fast on|off` 只把状态写入当前 Pi session（会话）的 Custom Entry（自定义记录）；恢复同一会话时恢复，其他会话不受影响。
- 禁止从全局或项目配置继承默认开启状态，其他会话不得受到当前会话影响。
- 在 session tree（会话树）切换分支时，状态沿当前分支记录恢复，不会从另一条分支泄漏。
- Fast Mode 状态以 `pi-dfast-state` Custom Entry（自定义记录）写入当前 session，不进入 LLM context（模型上下文）。新会话没有该记录，因此一定关闭；恢复已有会话或切换会话树分支时，只读取当前分支最后一条有效记录。
- 在 `--no-session` 或尚未产生持久化 session file（会话文件）的临时进程中，开关只对该进程有效；正常交互会话产生会话文件后才能在下次恢复时还原。

## 请求注入

- 开启且当前模型受支持时，在 `before_provider_request` 阶段只增加：

```json
{
  "service_tier": "priority"
}
```

- 只增加 `service_tier: "priority"`，不修改 Prompt（提示词）、verbosity（回答详略）、thinking level（思考等级）或其他采样参数。
- 同时检查当前 Pi 模型和 provider payload（提供方请求载荷）的模型，避免错改其他请求。
- 不读取或修改认证信息，不支持 API Key（API 密钥）提供方。

## 支持模型

当前只允许 `openai-codex` 的以下模型：

- `gpt-5.4`
- `gpt-5.5`
- `gpt-5.6-luna`
- `gpt-5.6-sol`
- `gpt-5.6-terra`

`gpt-5.4-mini` 与 `gpt-5.3-codex-spark` 当前不在允许列表。允许列表表示本地会注入 Priority Service Tier（优先服务等级），不构成服务端 entitlement（资格）或实际加速证明。

允许列表的唯一实现来源是 `src/fast-mode.ts` 的常量；本节是它的人读副本，改动以代码为准。

## 公开状态协议

消费者通过 Pi 事件总线使用以下事件：

- `pi-dfast/subscribe` / `pi-dfast/unsubscribe`：载荷为 `{ version: 1, consumerId: string }`。
- `pi-dfast/updated`：载荷为版本化 `DFastSnapshot`，包含开关状态、当前模型、本地是否满足注入条件、原因和更新时间。

快照中的 `active` 表示本地会为当前模型请求注入 Priority Service Tier（优先服务等级），不表示服务端已经确认 Fast Mode 生效。

首个结构化消费者订阅后，`pi-dfast` 清除原生 `dfast` status；最后一个消费者取消订阅后恢复，避免自定义 Footer 重复展示同一状态。

- 通过 `setStatus("dfast", ...)` 提供原生状态，并发布 `pi-dfast/updated` 版本化快照；有结构化消费者时隐藏原生状态，避免 Footer 重复显示。
- 不调用 `setFooter()`；只使用公开 `setStatus()` 和版本化事件协议。
- 不把“已开启”误写成“服务端已确认”；`active` 仅表示当前请求满足本地注入条件。

## 与其他扩展协作

- `pi-dusage`：Fast 对当前 Codex 模型变为活动时立即合并刷新 quota（配额）。
- `pi-dstatus`：独立 `fast` 组件显示 `FAST` 或 `FAST · inactive`；关闭时隐藏。

三者只通过版本化 Pi 事件协议连接，不读取彼此私有配置。
